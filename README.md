# My Telegram Bot (Next.js + grammY + Supabase)

## راه‌اندازی
1. `npm install`
2. در Supabase یک پروژه بسازید و از بخش **Connect**، رشته اتصال PostgreSQL را بردارید. برای Vercel از **Transaction pooler** استفاده کنید.
3. فایل `.env.example` را به `.env.local` کپی و مقادیر را پر کنید؛ رشته اتصال Supabase را در `DATABASE_URL` قرار دهید.
4. `ADMIN_PASSWORD` را برای دسترسی به پنل مدیریت تنظیم کنید و یک `SESSION_SECRET` تصادفی ۶۴ کاراکتری بسازید؛ آن را هم در `.env.local` و هم در Environment Variables و Vercel تنظیم کنید.
5. `npm run db:push`  ← ساخت جدول‌ها در Supabase
6. پروژه را روی GitHub بگذارید و در Vercel ایمپورت کنید
   (Environment Variables را هم در Vercel وارد کنید)
7. بعد از دیپلوی، `APP_URL` را در `.env.local` بگذارید و اجرا کنید:
   `npm run webhook:set`

در Supabase مسیر **Project Settings → Database → Connect** را باز کنید و رشته **Transaction pooler** را انتخاب کنید. اگر رمز دیتابیس شامل کاراکترهای خاص است، آن را در URL encode کنید. مقدارهای واقعی را فقط در `.env.local` و تنظیمات محیطی Vercel قرار دهید؛ فایل `.env.local` را منتشر نکنید.


.

## پنل مدیریت
- صفحه `/admin` فقط با ورود به سیستم قابل دسترسی است.
- رمز عبور پنل از متغیر `ADMIN_PASSWORD` خوانده می‌شود.
- ورود از `/admin/login` انجام می‌شود و نشست مدیریت با `SESSION_SECRET` امضا می‌شود
- مدیریت روزمرهٔ بات از منوی تلگرام «⚙️ تنظیمات» انجام می‌شود؛ پنل وب فعلی حفظ شده و هنوز از نقش‌های تلگرام مجوز نمی‌گیرد.
- بعد از دریافت تغییرات این نسخه، پیش از اجرا یا دیپلوی `npm run db:push` را اجرا کنید تا ستون‌ها و جدول‌های جدید در PostgreSQL ساخته شوند.
- ادمین اصلی با `OWNER_ID` تعیین می‌شود و همهٔ مجوزها را دارد. برای افزودن ادمین، از «تنظیمات ← کاربران» کاربر را جستجو و دکمهٔ «افزودن به ادمین‌ها» را بزنید؛ یا پیام کاربر را برای بات فوروارد کنید و با `/addadmin` به آن پاسخ دهید. همچنین `/addadmin <آیدی>` مستقیماً راهنمای افزودن را باز می‌کند. سپس یک قالب «پشتیبان»، «ناظر»، «مدیر فنی» یا «انتخاب دستی» را برگزینید و در صورت نیاز لقب و مجوزهای جداگانه را ویرایش کنید.
- قابلیت‌های اضافه‌شده: داشبورد، جست‌وجو و جزئیات کاربران، مسدودی موقت/دائمی، مدیریت ادمین‌ها و گزارش اقدامات، مدیریت گزارش‌های کاربران و بازخوردها، استیکر پردازش، حالت تعمیرات و روشن/خاموش‌کردن بخش‌های ویس/ارز/اخبار.
- تنظیم محدودیت نرخ از پنل فقط زمانی اثر دارد که Upstash Redis تنظیم شده باشد؛ در صورت قطع یا نبود Redis، محدودکننده مانند قبل fail-open است.
- فاز پایش: سلامت دیتابیس، وبهوک تلگرام، Redis و سرویس‌های Gemini/CoinGecko فقط در منوی ادمین مجاز نمایش داده می‌شود. خطاهای عملیاتی با پیام امن ذخیره و حداکثر هر ۱۵ دقیقه برای هر خطای تکراری به ادمین اصلی اعلان می‌شوند؛ خطاها پس از ۳۰ روز پاک می‌شوند.
- خروجی کاربران CSV/JSON در تلگرام نام و شناسهٔ واقعی را افشا نمی‌کند؛ شناسه با HMAC ناشناس‌سازی می‌شود و حداکثر ۱۰٬۰۰۰ ردیف صادر می‌شود. آمار مدیریتی به‌صورت تجمیعی است. راهنمای پشتیبان‌گیری در بات قرار دارد، اما خود بات فایل پشتیبان خام تولید یا پایگاه داده را بازیابی نمی‌کند.

## تبدیل رسانه
- تبدیل فقط پس از انتخاب «استیکر و گیف» یا «ویدیو مسیج» از منوی اصلی فعال می‌شود؛ ارسال رسانه به‌تنهایی دیگر باعث پاسخ یا تبدیل نمی‌شود. هر بار ورود برای یک رسانه است و برای تبدیل رسانهٔ بعدی باید دوباره بخش را انتخاب کرد.
- بخش «استیکر و گیف»: ویدیو → انیمیشن MP4 یا استیکر ویدیویی؛ GIF → استیکر ویدیویی؛ عکس → استیکر ثابت یا انیمیشن MP4؛ استیکر ثابت → تصویر یا انیمیشن MP4؛ استیکر ویدیویی → انیمیشن MP4.
- بخش «ویدیو مسیج»: ویدیو → ویدیو مسیج؛ ویدیوی بیشتر از ۶۰ ثانیه تا ۶۰ ثانیه بریده می‌شود. استیکرهای TGS و custom emoji پشتیبانی نمی‌شوند.
- برای استیکر ثابت و ویدیویی، هم ارسال تکی و هم افزودن به پک واقعی در دسترس است. برای هر کاربر پک ثابت و پک ویدیویی جداگانه ساخته و با پسوند استاندارد `_by_<bot_username>` نام‌گذاری می‌شود.
- سقف دانلود ورودی ۲۰ مگابایت، سقف خروجی عمومی ۱۰ مگابایت، سقف استیکر ۲۵۶ کیلوبایت و سقف استیکر ویدیویی ۳ ثانیه است.
- برای جلوگیری از پردازش دوبارهٔ آپدیت‌های طولانی، در Environment Variables پروژهٔ Vercel مقدار `WEBHOOK_ACK_FIRST=1` را تنظیم کنید. زمان اجرای ۳۰۰ ثانیه‌ای نیز فقط در پلن‌هایی قابل استفاده است که این سقف را پشتیبانی می‌کنند.

## اخبار روز
- خبرها از RSS ایران‌اینترنشنال (`https://www.iranintl.com/feed`) خوانده می‌شوند؛ برای این بخش Gemini لازم نیست.
- منوی اخبار روز شامل همهٔ خبرها، خبرهای جدیدِ دسته‌های انتخاب‌شده، خبرهای ذخیره‌شده، خبرهای خوانده‌شده، تازه‌سازی فید و تنظیمات است. فهرست‌ها صفحه‌بندی می‌شوند و مشاهدهٔ همه، دسته‌های ذخیره‌شده را تغییر نمی‌دهد.
- انتخاب دسته‌ها در تنظیمات تا زدن «ثبت تغییرات» موقت می‌ماند؛ اعلان خودکار نیز فقط برای دسته‌های ذخیره‌شده ارسال می‌شود.
- خبرهای بازشده خوانده‌شده محسوب می‌شوند و امکان ذخیرهٔ خبرها وجود دارد.
- اعلان خبرهای تازه برای دسته‌های انتخاب‌شده اختیاری است؛ کاربر آن را از منوی خبر روشن یا خاموش می‌کند. اعلان‌ها روزی یک‌بار، ساعت ۰۰:۰۰ به وقت UTC، با Vercel Cron بررسی می‌شوند و به `CRON_SECRET` نیاز دارند.
- فید در دیتابیس ۱۲ دقیقه کش می‌شود؛ فهرست، تیترهای راست‌چین و دکمه‌های کوتاه شماره‌دار دارد. با انتخاب هر خبر، کارت آن در پیامی جداگانه با تیتر برجسته، چکیده در قالب نقل‌قول (با حفظ پاراگراف‌های فید)، زمان انتشار، دسته و عکس موجود نمایش داده می‌شود؛ از کارت خبر می‌توان متن کامل را در وب‌سایت منبع باز کرد.
.
